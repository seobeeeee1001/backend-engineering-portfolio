## 1. 메시지의 저장 결과와 화면 표시 일치

**SnapBook · Java / Spring Boot / MySQL / WebSocket**

*별도 개선 구현 · 격리 환경 검증*

상담과 예약을 하나의 채팅방에서 진행하는 서비스입니다. **응답이 없다고 저장에 실패한 것은 아닙니다.** 저장 전 중단과 저장 후 응답 유실을 구분하지 않으면 재시도가 중복 저장으로 이어질 수 있었습니다.

- **구현:** 저장 결과를 확인해야 전송 완료로 표시하고, 결과를 받지 못하면 같은 메시지 ID로 재시도합니다. 서버는 기존 저장 결과를 반환하며, 재접속 후 이력을 조회해 화면을 복구합니다.
- **검증:** 서버 수신 전·DB 커밋 전·커밋 후 결과 수신 전의 중단을 재현했습니다. 각 조건에서 재시도·복구 후 DB와 발신자 화면에 메시지 1건이 유지되는지 확인했습니다.

## 2. 결제 실패 복구와 주문별 이용 기간 보존

**한능검 유료 학습 서비스 · TypeScript / PostgreSQL / Toss Payments**

**내부 저장을 롤백해도 외부 결제 승인은 취소되지 않습니다.** 승인 요청 기록을 먼저 남겨, 이후 이용권 저장이 실패해도 지급을 복구할 수 있도록 했습니다.

- **승인 복구:** 기록한 결제 키로 재조회해 주문번호·금액을 대조합니다. 주문을 잠근 뒤 지급 여부를 다시 확인해 중복 지급을 막습니다.
- **환불 처리:** 주문별 이용 기간을 기록하고 환불 주문의 미사용 기간만 제거합니다. 3일권 환불 시 별도로 구매한 하루 연장은 보존하고, 늦은 승인 결과로 환불 주문을 다시 지급하지 않습니다.
- **검증:** 결제사 응답을 모의하고 승인 후 DB 저장을 강제로 실패시켰습니다. 재조회로 한 번만 복구되는지, 반복 환불 통보에도 다른 구매의 기간이 유지되는지 확인했습니다.
