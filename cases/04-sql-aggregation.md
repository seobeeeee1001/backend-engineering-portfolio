# 집계 의미를 유지한 SQL 개선

[← 전체 사례](../README.md)

**프로젝트:** 한능검 운영 관리 화면

**맡은 범위:** 행동 지표 조회 지연 진단, SQL 재작성, 집계 정확성·실행 시간 확인

## 문제와 판단

관리 화면에서 행동 지표 탭을 눌러도 다음 화면이 열리지 않았습니다. 화면 동작을 따라가며 데이터 조회를 확인했고, 방문자와 행동을 연결하는 집계 쿼리의 지연으로 범위를 좁혔습니다.

집계에는 같은 방문자 식별자로 남은 행동과, 그 방문자가 로그인한 계정의 다른 기기 행동이 모두 필요했습니다. 원래 쿼리는 이를 `OR`와 상관 서브쿼리로 한 번에 결합했습니다. 두 경로를 단순히 더하면 같은 행동을 두 번 셀 수 있어, 결합 방식과 최종 집계 기준을 함께 확인했습니다.

## 변경

| 변경 전 | 변경 후 |
| --- | --- |
| 방문자 조건과 회원 조건을 `OR`·상관 서브쿼리로 결합 | 방문자 등호 결합과 회원 등호 결합을 각각 수행한 뒤 `UNION ALL` |
| 운영자·무제한 체험 계정 여부를 행별 상관 서브쿼리로 판정 | 내부 계정 집합을 `internal` CTE로 정의해 재사용 |
| 사람별 행동 인원 집계 | 최종 `COUNT(DISTINCT)` 유지 |

방문자·회원별 기존 인덱스를 활용할 수 있는 등호 결합으로 바꾸고, 랜딩 이후의 행동만 연결하는 시간 조건을 유지했습니다. 가입자 집계도 같은 방식으로 분리했습니다. 인덱스나 스키마를 추가하지 않은 변경입니다.

`UNION ALL` 단계에서 겹치는 행이 생겨도 최종 집계는 행동한 사람의 고유 수를 셉니다. 이 전제가 있으므로 중복 행을 허용할 수 있습니다. 이벤트 횟수나 금액 합계를 계산하는 쿼리라면 같은 방식이 그대로 성립하지 않습니다.
